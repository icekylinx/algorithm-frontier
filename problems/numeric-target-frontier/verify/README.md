# Verification and partial proof scope

The [central proof](../proof.md), [complete source map](../sources.md) and
[scoped core audit](../reference-realization.md) have distinct roles. This
increment reviews BC's central budget classification, the complete UP and CC
representations and their direct bounded-profile recovery/counts. It does
not mark the entire refinement family ready.

## Mathematical scope

The audit checks original optional-versus-mandatory semantics, zero-target
and eligibility preparation, signed zero-column scalars, shared-copy rank
projection and full original mass. It checks CC's common stopping-order
chain completeness, including tied stops; the exact class-count integral
intersection; occupied DFS failure accounting; and the Bell injection.
The direct upper/equality composition bound uses exact positive supports,
not coefficient magnitudes or a claimed constant row dimension.

The separate full UP mathematical audit checks useful support-block
prefixes, stopping ordinals and interval counts, polynomial copied ground,
support and target accounting and uniform binary space. UP's stronger
mixed-support algorithm is not implemented by this CC reference.

The central BC audit checks both upper dependencies, monotonicity in the
parameter budgets, the hidden-matroid construction and randomized transcript
bound, both all-budget calibrations and the uniform constant. Its lower
bound concerns worst-case instances under upper parameter budgets and rank
queries. It is not a lower bound for each exact parameter pair, a readable-
program ETH result, or hardness for every represented class.

The seven approximation schemes/constants, remaining fixed-dimensional and
single-objective refinements, encoded ETH families, support-geometric
refinements and nonlinear/global/mandatory/robust transfers retain their
linked statements and dependencies outside this partial audit. Missing
software is not being classified as an unresolved mathematical primitive.

## Native executable evidence

```sh
python3 problems/numeric-target-frontier/verify/check_targets.py
```

The [CC reference](../reference/README.md) is compared against an independent
original-input integer oracle. The checker supplies:

- 104 original mixed-target instances and 208 exact signed minimum/maximum
  optimizations, including 146 infeasibility answers. Every actual optimum
  and output is compared with original resource/row/eligibility constraints.
- 88 compiled cover chains and 92 independently enumerated bounded profiles;
  chain-copy dimensions and safe identical-owner/column merges are checked.
- 256 actual coefficient-vector universes, each compared with independent
  exhaustive multiplicity vectors and its support-composition count bound.
- Overlapping and tied-stop covers, capped large coefficients, shared
  capacity, absent zero classes, zero-target masking, signed real zero
  columns and optional-versus-mandatory mass distinctions.
- A 101-bit original rank with exact mandatory residual mass; actual zero-row
  signed greedy without LP calls; mandatory rank-loss rejection; empty ground
  and rank-zero branches; and 1,100 occupied DFS levels without recursion.
- A producer-disabled original-output verifier, four forged original outputs
  and eight malformed input/profile rejections.

The independent comparator reads only original data and uses no preparation,
chain, class, LP or target helper. Tiny numerical count enumeration belongs
to that test oracle, never the backend. Finite checks establish the reported
identities on those inputs, not general asymptotic profile or lower bounds.
The general mathematical arguments remain symbolic proofs.

## Cost and interface boundaries

Complete original rank tables and subset-pair axiom validation are charged
input work. Cover permutations and occupied profiles are streamed. The native
solver represents copied resource inequalities through original subset rows,
not an exponential table on the copied ground. Per-class total elimination
and generic exact fixed-coordinate substitution reduce the active dimension.
Its potentially exponential exact active-system LP factor is charged
separately from the paid polynomial SFM/intersection primitive in CC.
Workspace and rational records remain polynomial in the complete original
encoding, including binary rank and targets. No unit expansion is used.

Only one arbitrary rational scalar is optimized. A threshold on that same
scalar can be decided by the appropriate extremum. There is no additional
unrelated unbounded scalar constraint while optimizing a second scalar,
no signed numeric target row, and no extra independent resource rank.
Optional disposal is never supplied to a mandatory original-base problem.

Internal review, exact finite checks and original-output verification are
not proof-assistant formalization, external peer review or an exhaustive
public-priority audit. Repository surface checks validate syntax, links and
catalogue consistency rather than mathematical correctness.
