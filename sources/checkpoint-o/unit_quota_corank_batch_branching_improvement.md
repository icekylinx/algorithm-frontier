# Single-exponential corank time by branching on a required omission batch

**25 October 2026. Sharpening of the corank gap theorem; independent audit requested.**

This note replaces the one-player branching step in
`unit_quota_corank_gap_branching.md` by a batch step. It improves the
running time from 2^{O(c log(c+1))} to 2^{O(c)} for every fixed quota
gap. It does not change the input model, the approximation factors,
the one-sided failure semantics, or the scheduling reconstruction.

## 1. The stronger local certificate

Retain the notation of the corank note. At a recursive ground Q, the
restricted player matroid has the original rank r, and d=|Q|-r.
Suppose deterministic submodular minimization produces a deficient
set S with f(S)<b|S|. Write

\[
          m=|S|,\qquad
          \ell=m-\left\lfloor\frac{f(S)}{t}\right\rfloor,
          \qquad R=\frac{t}{t-b}>1.
 \tag{B1}
\]

The deficiency and t>b imply 1<=ell<=m. Every t-unit basis I*
contained in Q satisfies

\[
       |I^*\cap S|\le\left\lfloor\frac{f(S)}{t}\right\rfloor,
                  \qquad |S\setminus I^*|\ge\ell.
 \tag{B2}
\]

Therefore ell>d certifies absence of a t-unit basis. This guard is
tested before any subset enumeration and keeps the bound valid on
unpromised inputs. If ell<=d, the deficiency also gives

\[
 \ell
    =m-\lfloor f(S)/t\rfloor
    \ge m-f(S)/t
    >m-bm/t
    =m/R.
 \tag{B3}
\]

The decisive fact is the ratio m/ell<R, rather than only m<Rd.

## 2. The batch recursion

If no deficient set exists, return any player basis exactly as in
the original procedure. Otherwise calculate ell. If ell>d, return
FAILURE. If ell<=d, enumerate all ell-element subsets D of S.
For each D, test whether M|(Q\D) still has rank r. If it does,
recurse on Q\D, always restricting the same original resource f.
Return the first successful basis, or FAILURE if every candidate
deletion fails.

For every promised basis I*, (B2) supplies at least one enumerated
D subseteq S\I*. This deletion preserves I*, hence preserves both
the player rank and the t-unit resource promise. Induction on d
proves that a promised node cannot fail. Returned b-unit bases are
valid by the same downward-closure and zero-extension proof as in
the original manuscript. Thus the batch procedure has exactly the
same correctness contract.

The case d=0 is immediate: every deficiency has ell>=1>d and is
rejected. Rank r=0 still returns the empty basis before starting.
The t=b=1 case still uses exact matroid intersection.

## 3. A node bound that also charges skipped candidate deletions

Define, for R>1,

\[
                         \Gamma(R)=\frac{R^R}{(R-1)^{R-1}}.
 \tag{B4}
\]

For integers m>=ell>=1, the usual binomial probability estimate
gives

\[
 {m\choose\ell}
   \le\left(\frac{m}{\ell}\right)^\ell
      \left(\frac{m}{m-\ell}\right)^{m-\ell}
   =\Gamma(m/\ell)^\ell.
 \tag{B5}
\]

When m=ell the right-hand side is interpreted as one, so the same
statement remains true. To see the estimate without invoking any
asymptotic approximation, use that the term
binom(m,ell) p^ell (1-p)^(m-ell) is at most one in the binomial
expansion of (p+(1-p))^m, with p=ell/m.

The derivative of log Gamma(x), for x>1, is
log(x/(x-1))>0. Thus (B3) and (B5) imply

\[
                         {m\choose\ell}\le\Gamma(R)^\ell.
 \tag{B6}
\]

For complexity accounting, every candidate D is counted as a child
even if its rank test fails. Such a child is terminal. This charges
the work of enumerating and rejecting deletions, as well as the
actual recursive calls. Every candidate child receives remaining
budget d-ell, which is nonnegative because of the guard.

Inductively, a node of remaining budget d has at most

\[
                              (d+1)\Gamma(R)^d
 \tag{B7}
\]

nodes in this augmented computation tree. Indeed, if it branches,
the induction hypothesis and (B6) give

\[
 \begin{aligned}
 1+{m\choose\ell}(d-\ell+1)\Gamma(R)^{d-\ell}
   &\le 1+(d-\ell+1)\Gamma(R)^d\\
   &\le(d+1)\Gamma(R)^d,
 \end{aligned}
 \tag{B8}
\]

because ell>=1 and Gamma(R)^d>=1. A terminal node trivially
satisfies the same bound. No estimate depends on the existence of
a promised solution.

Each node has polynomial oracle and bit cost, and each subset D is
generated by a polynomial-space combination iterator. Depth-first
search has depth at most c and retains polynomial workspace. The
improved gap running time is therefore

\[
 \boxed{\Gamma\!\left(\frac{t}{t-b}\right)^c
                              \operatorname{poly}(H).}
 \tag{B9}
\]

An alternative simpler bound is (e*t/(t-b))^c poly(H), since
Gamma(R)=R(1+1/(R-1))^(R-1)<=eR. These are analysis bounds only;
the algorithm computes integer ell and performs integer rank tests,
without numerically evaluating Gamma or exponentials.

## 4. Consequences for the accepted quota and scheduling statements

For t=4 and b=2, R=2 and Gamma(2)=4. Thus the critical four-unit
promise/two-unit output problem has deterministic time

\[
                                 4^c\operatorname{poly}(H).
 \tag{B10}
\]

For the factor-two optimization wrapper, t=K>=2 and
b=ceil(K/2), so R<=3 and Gamma(R)<=Gamma(3)=27/4. The unit allocation
algorithm consequently runs in

\[
                         (27/4)^c\operatorname{poly}(H)
                           =2^{O(c)}\operatorname{poly}(H)
 \tag{B11}
\]

time and returns an integer value at least ceil(OPT/2). The exact
one-unit branch handles K=1. The one-sided search and the
strict-below-two oracle lower bound are unchanged.

Substituting the same routine into
`two_size_makespan_corank_three_halves_transfer.md` preserves every
target and reconstruction step, including the exact factor 3/2
without an additive small-job term. Its running time improves to

\[
                         (27/4)^c\operatorname{poly}(H),
 \tag{B12}
\]

where c is the number of nonloop large-job positions minus the
number of large units. The empty-class and Boolean-rank-failure
branches remain polynomial. The strict-below-3/2 oracle obstruction
still matches the approximation threshold, but does not establish
that the exponential base or even an exponential dependence on c
is necessary at the threshold itself.

## 5. A useful continuous quota-ratio formulation

Whenever integer engineering in an application makes b=t/D exactly
for a rational D>1, the branch ratio becomes

\[
                 R=\frac{D}{D-1},
        \qquad\text{time }\left(\frac{eD}{D-1}\right)^c
                                      \operatorname{poly}(H).
 \tag{B13}
\]

For D=1+epsilon this is (O(1+epsilon^-1))^c poly(H). This observation
is a gap-algorithm consequence, not by itself an approximation
scheme for integer unit allocation. Small integer optimum values
can force t=b under a below-two multiplicative request, and that
case is excluded from the gap theorem except for the exact
one-unit special case. Any scheduling or workload application must
verify its own quota engineering and rounding separately.
